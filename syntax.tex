\section{Syntax of a Minimalistic Smart Contract Language}\label{sec:syntax}

We assume to analyze programs written in a minimalistic language.
It is just the kernel of an imperative object-oriented language for
smart contracts, with lists as containers. It is possible to add maps
as containers as well, but we only allow lists to keep
the presentation simple. Moreover, maps are seldom iterated in smart
contracts. In Solidity, they \emph{cannot} be iterated, by language design.
%
\begin{definition}[Expressions and Commands]\label{def:exp_com}
  The set of \emph{xpressions} $\Exp$ and the set of
  \emph{commands} $\Com$ are defined by the following grammar,
  where $c$ is an integer literal constant of the language,
  $v$ is a variable in $\Var$, $\mathit{aop}$ is an arithmetic
  operator ($+$, $-$, $*$\ldots) and $\mathit{cop}$ is a comparison operator
  ($<,\le,=,\not=$\ldots):
  \begin{align*}
    \exp::=&\ \mathit{c}\mid\mathit{v}\mid\field{\exp}{f}\mid\aop{\exp}{\exp}\\
    &\mid\new{C}{\exp^*}\mid\size{\exp}\mid\last{\exp}\mid\random{\exp}\\
    \com::=&\ \assign{\mathit{v}}{\exp}\mid\assign{\field{\exp}{f}}{\exp}
    \mid\require{\exp}{\exp}\\
    &\mid\push{\exp}{\exp}\mid\receive{\exp}{\exp}\mid\call{\exp}{m}{\exp^*}\mid\nop\\
    &\mid\ife{\exp}{\exp}{\com}{\com}\mid\for{\mathit{v}}{\exp}{\com}\mid\sequence{\com}{\com}.
  \end{align*}
\end{definition}

\begin{definition}[Program]\label{def:program}
  A \emph{program} is a collection of \emph{classes}.
  Each class $C$ has a \emph{superclass}, some \emph{field signatures} $C.f$
  and some \emph{methods} $C.m$, declared as
  \[
  C.m(p_1:t_1,\ldots,p_n:t_n)\ \<let>\ l_1:t_1',\ldots,l_q:t_q'\ \<in>\ \com,
  \]
  where $\com$ is the \emph{body} of the method, $p_1\cdots p_n$ are its
  formal parameters, of type $t_1\cdots t_n$, and $l_1\cdots l_q$ are its
  local variables, of type $t_1'\cdots t_q'$. Local variables include the
  implicit variables \<this> (the \emph{receiver} of $C.m$),
  \<caller> (the calling contract of $C.m$) and \<now> (the current time).
  If $C.m$ is \<payable>, they also include \<amount>
  (the cryptocurrency paid for calling $C.m$).
  A class that extends \<Contract> is called a \emph{smart contract}.
  A \emph{constructor} is a method $C.C$ named like the class $C$ that declares it.
  A type is either \emph{primitive} (such as \<int>)
  or a class name $C$. Generic class types (such as lists) are written as
  \<List<t\texttt{>}>, where \<t> is the type of the elements of the list.
  Fields $C.f$ can be \<final>, if they are assigned exactly once in each
  constructor of $C$. We assume programs type-checked.
\end{definition}
